【菜鳥勇闖演算法】我對「二分搜尋法」的理解

發表於2026-02-04|更新於2026-02-08|演算法
|瀏覽量:

這是 Aloe【菜鳥勇闖演算法】的第一篇文章。這篇文章筆者與讀者一起手撕「二分搜尋法」。我們從生活中的真實例子出發，引出二分搜尋法的優點。

前言：關於「二分搜尋法」的直覺

找書

小明和 Siao 前往了圖書館。圖書館一共有 12345 本書，在同學們的維護下，書的編號是從小到大排列的，但是有些書本丟失了，他們想看看編號為 8000 的書本到底是否還在書架上。

  • 小明看著長長的書架一眼望不到頭，只好隨意翻弄書本。

  • Siao 先是走到了書架的正中間，看了一下這本書的編號是 6200，心想：「6200 比我要找的 8000 小，說明左邊這一半書架（1~6200）全是垃圾，看都不用看！」於是直接走到了右半邊区域的中間；發現書的編號是 9500，於是又向左走了一半 …… Siao 很快就發現編號 8000 的書本不在。

像 Siao 這樣每次都捨棄一半的搜尋空間（書本），在搜尋空間中不斷「二分」的演算法叫做「二分搜尋法】」。

思考： 如果書本的編號不是從小到大的有序排列，我們還能像這樣二分搜尋了嗎？

思考： 如果要找編號為 8001 的書本，並且這套書有很多卷（8001-A、8001-B、…）。小明和 Siao 要分別找 8001-A（第一卷） 和 8001-?（最後一卷），那麼找到某一卷 8001 之後就停手，可以嗎？還需要怎麼找？如何計算 8001 總共有多少卷？

猜數字遊戲

小明和 Siao 在玩一個猜數字遊戲，遊戲規則是在 1-100 之內喊一個整數，裁判會告訴玩家猜大了還是猜小了。Siao 心生一計，邪魅一笑；而小明卻不知所措。據說當時的遊戲情景是這樣的：

  • 小明：
    • 90！裁判：猜大了！
    • 20！裁判：猜小了！
    • 25！裁判：猜小了！
    • 40！裁判：猜小了！
    • 45, 55, 65, …
    • 好難，不要玩了…
  • Siao：
    • 先猜 (1+100) / 2 = 50
    • 50！裁判：猜小了！ -> 排除 1-50，鎖定範圍 [51, 100]，下一次猜 (51+100) / 2 = 75
    • 75！裁判：猜小了！ -> 排除 51-75，鎖定範圍 [76, 100]，下一次猜 (76+100) / 2 = 88
    • 88！裁判：猜大了！ -> 排除 88-100，鎖定範圍 [76, 87]，下一次猜 (76+87) / 2 = 81
    • 81！裁判：猜大了！ -> 排除 81-87，鎖定範圍 [76, 80]，下一次猜 (76+80) / 2 = 78
    • 78！裁判：猜小了！ -> 排除 76-78，鎖定範圍 [79, 80]，下一次猜 (79+80) / 2 = 79
    • 79！裁判：猜小了！ -> 排除 79，鎖定數字 80，下一次猜 80
    • 80！裁判：猜中！

Siao 只用了 7 步就猜中了數字，而小明卻仍然在亂猜。事實上觀察 Siao 喊出的數字可以發現，Siao 每次都是喊出當前已知的最小和最大的數字的平均值。

像 Siao 這樣每次都捨棄一半的答案空間（要猜的數字），這種在答案空間不斷「二分搜尋」的演算法叫做「二分答案」。

武器庫：一個通用的模板

必須承認的是，寫二分搜索的演算法時，最令人頭疼的不是程式碼的邏輯，而是邊界條件：

  • 要寫 while (left < right) 還是 while (left <= right)？

  • 要寫 mid + 1 還是 mid - 1？

這裡給出一個筆者在用的模板，筆者認為這個模板是比較符合正常的思維的，寫起來不會感到特別「反直覺」。

程式碼解讀：

  1. 我們預設 nums 陣列是「不降」的（也就是從小到大排列的）。

    • 如果得到了從大到小排列的陣列，可以呼叫 std::ranges::reverse() 或 std::reverse() 函式。
    • 或者把 > target 和 < target 的邊界調整互換。

    提示： 若需呼叫 std::ranges::reverse() 或 std::reverse() 函式，需包含 algorithm 標頭檔。其中 std::ranges::reverse() 需要 C++ 20。

  2. 第 6 列，這樣寫等價於 mid = (left + right) / 2，但是我們這種寫法能防止潛在的 left + right 加法溢出。

  3. 第 9 列，若滿足 nums[mid] < target，則說明我們找的數字小了。

    • 我們要找的數字的位置在 mid 右側，並且 mid 這個位置本身的數字也不是我們要找的。
    • 所以把 left 移至 mid + 1 的位置。

  4. 第 12 列，同第九列。

  5. 第 15 列，我們終於找到了一個數字，位置就是 mid。我們先保存起來。

    隨後我們面臨三個抉擇：

    • 如果我們只要確認「是否存在」，或者隨便找一個位置就好了，就直接跳出迴圈，傳回這個 ans。
    • 如果我們要找「左側邊界」，則把這個結果視為「找的數字大了」：right = mid - 1;
      • 這解答了思考題2：如何尋找 8001-A。
    • 如果我們要找「右側邊界」，則把這個結果視為「找的數字小了」：left = mid + 1;
      • 這解答了思考題2：如何尋找 8001-?。

  6. 第 23 列，我們可能傳回：

    • 一個非負整數。這代表我們在 nums 中搜尋到到的某一個值為 target 的位置。
    • 或者 -1。這代表整個迴圈流程中從未滿足 nums[mid] == target）條件，即在 nums 中未能找到 target。
      • 這也是找書問題中，未找到 8000 號書對應的情況。

  7. 時間複雜度是 O(log n)。

實戰演練：從卡殼到破局

題目一：A-B 數對，洛谷 P1102

A. 題目簡述：給定正整數陣列和正整數 C，從陣列中找出滿足 A - B = C 的數對的個數。

B. 第一直覺與暴力解法：

  • 寫一個兩層迴圈，暴力枚舉 A 和 B，時間複雜度 O(n2)：

    警告： 這道題 1 ≤ N ≤ 2 × 105，時間限制 1.00s。如果是 O(n2) 的時間複雜度，會有 1010 數量級次數的運算，會 TLE。

C. 思路卡殼：

  • 靈感：由於題目並未規定從陣列中取數字的先後次序，則可以「跳著選擇」。因此考慮將陣列排序後採用「二分搜尋法」找出符合要求的 A 和 B。

  • 困惑：但是由於需要搜尋兩個變數 A 和 B，與我們剛剛提到的「找書」問題有較大差異。開始懷疑「二分搜尋法」的正確性。

D. 破局點：

  • 轉換視角：考慮利用等式變換，將 A - B = C 問題變換為 A = B + C 問題。

  • 變數固定：考慮消去 B 變數，想到可以寫一個迴圈，每次選擇一個固定的 B，這樣就只剩 A 這一個變數，而要搜尋的數字 target 就等於 B + C。

  • 可行性驗證：外層迴圈，時間複雜度為 O(n2)；內層二分搜尋，時間複雜度為 O(log n)。總時間複雜度為 O(nlog n)，運算次數的數量級為 106，可以在 1.00s 時間內運行完畢。

  • 計算滿足要求數對的個數：這是思考題 2 的最後一個小問題。考慮計算出 target 的左邊界 ans_left 與右邊界 ans_right，之後算減法再 +1，即 Counttarget = ansright − ansleft + 1。

F. 程式碼壞味道與最佳化：

我們剛剛寫出的程式碼雖然可以正確地解決問題，可是卻有兩個幾乎一模一樣的 while 迴圈（計算左右邊界），這在工程中被稱作「程式碼壞味道」。

那麼，是否有一種方法可以省去這兩個幾乎完全一樣的迴圈呢？

使用 std::lower_bound 與 std::upper_bound 函式

提示： 若需呼叫 std::lower_bound 或 std::upper_bound 函式，需包含 algorithm 標頭檔。

  1. 呼叫： std::lower_bound(first, last, target);

    一般地，對整個 STL 容器搜尋（如 std::vector<int> nums）：

    • first = nums.begin()，last = nums.end()。

  2. 功能簡述： std::lower_bound 與 std::upper_bound 是 STL 提供的「二分搜尋法」函式，對於一個「升序」的陣列：

    • lower_bound：回傳在 [first, last) 中，第一個滿足 elem >= target 的位置（疊代器），若未能找到回傳 last。
    • upper_bound：回傳在 [first, last) 中，第一個滿足 elem > target 的位置（疊代器），若未能找到回傳 last。

    對於隨機存取容器，時間複雜度為 O(log n)。

  4. std::binary_search 簡述：

    • 呼叫：std::binary_search(first, last, target)，回傳一個布林值。
      • true：利用二分搜尋找到了一個 target。
      • false：未能找到一個 target。

    僅適用於確認「是否存在」，或者隨便找一個位置的情形。

G. 總結：

這道題我們首先利用等式的性質，變換為 A = B + C 的問題，同時利用一層迴圈固定 B 變數，這樣就是一個標準的「單變數」二分搜尋。

使用二分搜尋找出左右邊界。個數的計算公式為 Counttarget = ansright − ansleft + 1。

為了簡化二分搜尋的程式碼的編寫，我們學會了如何使用 std::lower_bound 與 std::upper_bound 函式，並得出新的計算公式為 Counttarget = itup − itlow。

思考題解答：

  • 由於 std::upper_bound 找的是「大於」的位置。相當於自動幫我們 +1 了，因此不需要另外 +1。

  • 如果 std::lower_bound 與 std::upper_bound 沒有找到 target，則 it_up == it_low，相減等於 0，符合計算直覺，不需要額外的 if 判斷。
